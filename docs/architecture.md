# 架构与后续路线

## 当前版本

`app.js` 消费 `store.js`，通过 `views.js` 将页面渲染到 DOM；`store.js` 管理版本化本机状态。界面不导入任何模型 SDK，也不执行用户输入的服务地址或插件代码。

配置、角色、消息、手动记忆及压缩图片写入当前来源的 localStorage。状态 schema v2 保持原存储 key，加载 v1 时添加默认主页与外观字段，保留原会话。备份导入重建允许的字段，校验数据，拒绝外部图片 URL 与任意 CSS 主题值。密钥输入禁用，状态结构无凭据字段。旧 Python 桌面代码只在 legacy 中保留用于对照，未来代码不依赖它。

## API 运行层（下一阶段）

添加独立的 provider adapter：输入角色、历史、模型配置和临时凭据，输出统一的文本增量、结束和错误事件。分别适配 OpenAI 兼容、Anthropic、Gemini 的协议。第一版的本机草稿应由用户明确选择后重新发送，不能接通模型后自动补发。

浏览器能否直连取决于服务商 CORS 和客户端调用支持。安卓打包后可评估原生 HTTP；不一定需要自建服务器。个人自带密钥通过设备安全存储管理，公共产品不能把开发者密钥嵌进安装包。

## MCP 与插件运行层

远程 MCP 和本地插件是两类实现。远程 MCP 需要协议握手、工具发现、认证、取消与错误处理；stdio MCP 必须由支持启动进程的宿主运行。浏览器无法直接运行任意 npx/uvx 服务，Operit 插件也不能自动通用。

执行层需要工具能力声明、权限范围、调用日志与用户确认机制。配置页目前不宣称连通，不将“保存配置”等同于安装或授权执行。

## 手机打包

当前是浏览器前端原型。确认 UI 后评估 Capacitor：将前端作为本地资源打入 APK，并增加键盘、安全区、文件分享、设备安全存储等桥接。引入 Capacitor 前核实当前官方依赖和安卓构建要求；APK 构建需要 Android SDK。此版没有 Android 工程或安装包。

## 账号额度

预留认证适配器，不把网页会话 Cookie 当作通用 API 凭据。以后根据官方开放的接入方式分别研究 ChatGPT 登录/额度授权和 Claude API 认证；不让账号接入成为第一版 UI 的依赖。

## 主页与外观

底部导航固定为 home / chat / memory / settings，初始页为 home。会话列表是对话页的次级入口；插件是设置里的分组。

壁纸和头像通过文件选择器载入，仅支持 PNG/JPEG/WebP，解码后重绘到 canvas；壁纸最长边 1440px，头像 256px，再压缩为 JPEG。这样本机数据与备份不会依赖临时 Blob URL。外观色彩通过 CSS 变量集中管理，主题色、玻璃底色透明度、模糊程度均可修改。

纪念日按设备本地日历日期计算，开始当天为第 1 天，不按毫秒跨度计算，避免夏令时干扰。

## 记忆

`memories` 为独立数组，每条记录含标题、内容、kind、创建时间、到期时间与可选来源。短期记忆到期后不出现在有效记忆列表；可在“已到期”查看、编辑或删除。永久记忆 expires 为 null。编辑短期记忆会从本次保存重新计算保留时长。记忆暂时不会自动进入模型请求，后续检索层需明确处理隐私、上下文预算与过期规则。
