# 架构与后续路线

## 当前版本

`app.js` 消费 `store.js`，将页面渲染到 DOM；`store.js` 管理版本化本机状态。界面不导入任何模型 SDK，也不执行用户输入的服务地址或插件代码。

配置、角色及消息写入当前来源的 localStorage。密钥输入禁用，状态结构无凭据字段。旧 Python 桌面代码只在 legacy 中保留用于对照，未来代码不依赖它。

## API 运行层（下一阶段）

添加独立的 provider adapter：输入角色、历史、模型配置和临时凭据，输出统一的文本增量、结束和错误事件。分别适配 OpenAI 兼容、Anthropic、Gemini 的协议。第一版的本机草稿应由用户明确选择后重新发送，不能接通模型后自动补发。

浏览器能否直连取决于服务商 CORS 和客户端调用支持。安卓打包后可评估原生 HTTP；不一定需要自建服务器。个人自带密钥通过设备安全存储管理，公共产品不能把开发者密钥嵌进安装包。

## MCP 与插件运行层

远程 MCP 和本地插件是两类实现。远程 MCP 需要协议握手、工具发现、认证、取消与错误处理；stdio MCP 必须由支持启动进程的宿主运行。浏览器无法直接运行任意 npx/uvx 服务，Operit 插件也不能自动通用。

执行层需要工具能力声明、权限范围、调用日志与用户确认机制。配置页目前不宣称连通，不将“保存配置”等同于安装或授权执行。

## 手机打包

当前是浏览器前端原型。确认 UI 后评估 Capacitor：将前端作为本地资源打入 APK，并增加键盘、安全区、文件分享、设备安全存储等桥接。引入 Capacitor 前核实当前官方依赖和安卓构建要求；APK 构建需要 Android SDK。此版没有 Android 工程或安装包。

## 账号额度

预留认证适配器，不把网页会话 Cookie 当作通用 API 凭据。以后根据官方开放的接入方式分别研究 ChatGPT 登录/额度授权和 Claude API 认证；不让账号接入成为第一版 UI 的依赖。
