# moom 初版

moom 是手机桌面中的独立剧情入口，与消息 App 共用角色资料和聊天关联。
参考用户提供的 `offline_story_flow_invite_scene_sidebar.html` 的阅读、侧栏、邀请及小记流程；正式应用界面与交互独立实现，不加载演示里的外部图标字体。

## 入口与外观

- 底部固定为消息、moom、外观、设置；记忆移到桌面 App 页，旧布局优先补到已有的 App 页。
- moom 使用 Nucleo 官方免费 Glass `star-sparkle` 图标，记忆沿用 `hearts`。后续入口图标继续优先选 Nucleo，使用前确认对应素材许可。
- 全屏无气泡阅读；旁白与台词使用已有本地思源宋体，英文使用 Cormorant Garamond。用户台词／行动靠右，正文保持可读对比。
- 海蓝、雾白、淡粉、鼠尾草、暮紫五种轻微场景色；跟随全局日夜、壁纸与玻璃材质。
- moom 左上角用统一的 44px 无背景侧栏按钮，代替返回箭头；右侧不重复放侧栏按钮。抽屉继续向下拖动收起，没有右上角关闭叉。Moom 侧栏与线上聊天共用框架、个人资料区、导航与底部操作；收起也使用侧栏图标。

## 当前可以实际操作的内容

1. 新建、编辑场景名称、地点、场景时间、开场设定、氛围色与关联聊天。
2. 直接开始，或先在关联聊天放入一份由自己发起的邀请；聊天「＋」也可直接打开这个表单。
3. 邀请可接受或暂缓；暂缓后保留查看入口。接受后显示场景标题，点击进入正文。
4. 统一输入框可写台词或描述行动，自定义状态文字可以点击编辑；提交的回应会保存本机。
5. 暂存／继续；开始另一幕会暂存前一幕。返回桌面只离开界面，不自动结束剧情。
6. 结束时填写小记，在关联聊天生成记录卡；点击卡片重读，已结束的场景不再显示输入框。
7. 场景、输入方式、正文类型、自定义状态文字、小记及邀请关联随 JSON／ZIP／本机快照保存。输入框中尚未提交的草稿仅在当前页面会话保留。

## 当前边界

尚未调用模型，没有自动生成开场、流式续写、自动摘要、AI 主动邀请、后台运行或自动记忆提取。
正式场景不会伪造 AI 对白、生成状态或呼吸点。当前小记由用户填写，记录卡也以用户记录保存。
场景时间是用户设定的标签，不会更改设备时间，也不构成已实现的统一世界时钟。
角色资料共用，场景用 `sessionId` 关联聊天；后续模型接入需要同时读取对应聊天与场景上下文，当前尚不自动向模型注入记忆。
关联聊天删除后仍可在 moom 阅读场景，返回聊天时提示其已删除，不重建或捏造原聊天。

## 隔离示例

打开 `?preview=moom`，或点击 moom 空状态的「先看一幕示例」。
这里有海边正文、较早场景和关联卡片，可试输入、编辑状态栏文字、侧栏、暂存、结束及日夜模式。
示例使用独立内存状态、媒体和快照存储，不读写正式聊天、音频或备份数据库；刷新重置。
正文和关联聊天均标示示例性质，模型不产生真实回复。

## 数据

记录 schema 继续为 v2，新增可选根字段：

```js
moom: {
  active: 'scene-id',
  scenes: [{
    id, title, pinned, place, timeLabel, premise, tone, sessionId,
    status, // invited | deferred | active | paused | ended
    statusPanel: {weather, mood, condition},
    created, updated, summary,
    entries: [{id, kind, text, time, bookmarked}]
    // kind: narration | dialogue | say | act
  }]
}
```

聊天记录的 `storyLink:{kind:'invite'|'record',sceneId}` 引用同一幕。缺失引用有可读降级提示。
旧备份缺少 moom 时补空集合，已有聊天、相册、媒体和外观保留。归一化过滤非法条目、重复 ID 和无效场景色，所有用户／导入文字经转义后呈现。

## 2026-10-18 侧栏精简与共用长按菜单

- 两边均去掉导航区／底部操作区的内部横向分割线；保留玻璃侧栏外缘。moom 的场景行只显示标题、日期，去掉状态小字、彩色圆点和右侧箭头。
- moom 顶部使用已有的用户昵称 `home.userName`，不再写固定的 Moom 标题；头像仍沿用用户头像。线上侧栏中的 moom 入口使用 Lucide 官方 moon-star 线条图标，桌面 Nucleo 图标不变。
- 场景与对话侧栏的行均支持长按 520ms、右键或 Shift+F10／菜单键，打开同一个玻璃抽屉：置顶（已置顶时为取消置顶）、重命名、删除。正常点击仍进入记录；移动超过 8px、滚动或 pointercancel 会取消长按。长按后松手不会触发进入。
- 置顶场景显示在独立「置顶」分组，标题／日期格式保持一致；置顶及重命名不改变场景活动日期。`pinned` 为可选兼容字段，旧记录默认为 false，随 ZIP／JSON 保存。
- 删除场景保留聊天，聊天中的关联卡片使用既有缺失场景提示；删除聊天保留已收藏记忆和关联剧情。删除最后一段聊天会创建空会话以维持合法状态。删除有二次确认，重命名／存储失败保留输入并回滚记录。
- `src/sidebar-menu/` 统一模型、菜单呈现、长按与关闭逻辑；两边复用同一控制器，不在行尾重新增加操作按钮。
- 87 项测试和语法检查通过；验证真实 CDP 触控长按／松手／滑动取消，场景和聊天的持久化操作、失败回滚、菜单嵌套与焦点恢复；多尺寸昼夜布局及正式入口／预览的渲染一致性继续通过。

## 2026-10-18 角色页头、输入区与默认状态栏

- 忽略此前 4:3 请求，保持按设备视口响应布局，没有锁定宽高比。页头保留左侧侧栏开关，中间显示当前 `persona.name` 和 `appearance.aiAvatar`；右侧为「…」场景菜单。预览标识复用角色副标题，退出入口位于菜单内，不另占版面。
- 默认界面删除场景编号、参与双方行、旧场景状态行、空白剧情提示、底部收藏按钮／连接状态文字及说话／行动切换。原有行动类型历史记录仍能阅读。
- 输入区为上排「＋／重说／继续」顺序，下排独立的玻璃文本框与圆形发送按钮；统一文本框同时接收台词和行动描述，不会擅自拆分或替用户编写动作。
- 「＋」打开真实的状态栏编辑、场景设定和收藏片段入口；「…」管理暂存、结束、回到聊天等行为。
- 默认剧情版头是可编辑的玻璃状态卡，包含场景名称、时间、地点、天气、心情及可选的人物状态。时间／地点复用已有场景字段，新 statusPanel 不复制角色或记忆。未填写显示「未设定」，正式场景不编造天气、心情或人物动作。示例的状态值只属于隔离示例。
- 状态栏编辑随本机记录、ZIP、JSON 保存，旧记录缺少字段时补空值；文字全部转义，字段有长度限制，不执行酒馆 HTML／脚本。它不是已接通的自动状态推演或世界时钟。
- 重说与继续保留图标入口，但以 aria-disabled 标记当前不可用，点击说明模型未连接，保留草稿和正文；不伪造生成或替换示例段落。
- 沿用既有检查并扩展状态数据的旧记录兼容与 ZIP／JSON 往返。浏览器验证角色头像／昵称来源、删除项、操作顺序、状态保存／刷新／存储失败保留输入、收藏访问、320px／横屏／平板昼夜及正式与预览页面样式一致性。实体手机尚未实测。
