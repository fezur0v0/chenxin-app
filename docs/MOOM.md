# moom 初版

moom 是手机桌面中的独立剧情入口，与消息 App 共用角色资料和聊天关联。
参考用户提供的 `offline_story_flow_invite_scene_sidebar.html` 的阅读、侧栏、邀请及小记流程；正式应用界面与交互独立实现，不加载演示里的外部图标字体。

## 入口与外观

- 底部固定为消息、moom、外观、设置；记忆移到桌面 App 页，旧布局优先补到已有的 App 页。
- moom 使用 Nucleo 官方免费 Glass `star-sparkle` 图标，记忆沿用 `hearts`。后续入口图标继续优先选 Nucleo，使用前确认对应素材许可。
- 全屏无气泡阅读；旁白与台词使用已有本地思源宋体，英文使用 Cormorant Garamond。用户台词／行动靠右，正文保持可读对比。
- 海蓝、雾白、淡粉、鼠尾草、暮紫五种轻微场景色；跟随全局日夜、壁纸与玻璃材质。
- 复用统一的 44px 无背景返回按钮与可向下拖动的抽屉。抽屉没有右上角关闭叉；Scenes 是带返回箭头的侧栏。

## 当前可以实际操作的内容

1. 新建、编辑场景名称、地点、场景时间、开场设定、氛围色与关联聊天。
2. 直接开始，或先在关联聊天放入一份由自己发起的邀请；聊天「＋」也可直接打开这个表单。
3. 邀请可接受或暂缓；暂缓后保留查看入口。接受后显示场景标题，点击进入正文。
4. 说话／行动输入、片段收藏及仅看收藏；提交的回应会保存本机。
5. 暂存／继续；开始另一幕会暂存前一幕。返回桌面只离开界面，不自动结束剧情。
6. 结束时填写小记，在关联聊天生成记录卡；点击卡片重读，已结束的场景不再显示输入框。
7. 场景、输入方式、正文类型、片段收藏、小记及邀请关联随 JSON／ZIP／本机快照保存。输入框中尚未提交的草稿仅在当前页面会话保留。

## 当前边界

尚未调用模型，没有自动生成开场、流式续写、自动摘要、AI 主动邀请、后台运行或自动记忆提取。
正式场景不会伪造 AI 对白、生成状态或呼吸点。当前小记由用户填写，记录卡也以用户记录保存。
场景时间是用户设定的标签，不会更改设备时间，也不构成已实现的统一世界时钟。
角色资料共用，场景用 `sessionId` 关联聊天；后续模型接入需要同时读取对应聊天与场景上下文，当前尚不自动向模型注入记忆。
关联聊天删除后仍可在 moom 阅读场景，返回聊天时提示其已删除，不重建或捏造原聊天。

## 隔离示例

打开 `?preview=moom`，或点击 moom 空状态的「先看一幕示例」。
这里有海边正文、较早场景和关联卡片，可试输入、收藏、侧栏、暂存、结束及日夜模式。
示例使用独立内存状态、媒体和快照存储，不读写正式聊天、音频或备份数据库；刷新重置。
正文和关联聊天均标示示例性质，模型不产生真实回复。

## 数据

记录 schema 继续为 v2，新增可选根字段：

```js
moom: {
  active: 'scene-id',
  scenes: [{
    id, title, place, timeLabel, premise, tone, sessionId,
    status, // invited | deferred | active | paused | ended
    created, updated, summary,
    entries: [{id, kind, text, time, bookmarked}]
    // kind: narration | dialogue | say | act
  }]
}
```

聊天记录的 `storyLink:{kind:'invite'|'record',sceneId}` 引用同一幕。缺失引用有可读降级提示。
旧备份缺少 moom 时补空集合，已有聊天、相册、媒体和外观保留。归一化过滤非法条目、重复 ID 和无效场景色，所有用户／导入文字经转义后呈现。

Chromium 验证 320×640、390×844、844×390、768×1024 的日夜布局，另在 375×812 普通动画下检查真实触控拖动、键盘焦点、存储失败保留输入、跨聊天草稿隔离及关联聊天删除后的重读。
真实下载 ZIP 并恢复到独立浏览器环境，确认场景与卡片关联保留。未在实体 Android／iOS 设备上测试。
