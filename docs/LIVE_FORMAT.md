# 线上 / 线下 正文格式规范（草稿）

> **状态：设计稿，尚未实现。**
> 本文写的是「对话」与 moom 合并后的打算，现在的 app 里还没有这些功能。
> 当前仍有独立的 moom 入口，底栏仍是「对话、moom、外观、设置」；模型尚未接入，自动记忆、AI 主动邀请、世界时钟等能力也都还没有。

---

## 1. 目标：一个「对话」，正文里有线上和线下

以前有两个入口：「对话」和「moom」。合并后只留一个 **「对话」**。

AI 回复的正文有两种表达形式：

- **线上**：手机上的聊天。用 `<live>` 和 `</live>` 包起来，显示成聊天气泡。
- **线下**：现实里发生的事、动作、环境、心理。写在 `<live>` 外面，显示成整段文字的阅读排版（沿用现在 moom 的样子）。

要点：

- 线上和线下是 **同一条正文里的两种写法**，不是两种会话。
- 界面 **不显示** 「线上 / 线下」标签，**没有** 切换按钮，也 **不区分** 会话类型。
- 什么时候用线上、什么时候用线下，**完全由模型按剧情自己判断**。可以整条都是线上、整条都是线下，也可以随意穿插。
- 本规范只管「怎么写」和「怎么显示」。

### 合并后的底栏

moom 入口删除，「外观」从桌面移到底栏：

```
┌───────────────────────────────────────┐
│                                       │
│              （桌面内容）               │
│                                       │
├─────────┬─────────┬─────────┬─────────┤
│  对话   │  记忆   │  外观   │  设置   │
└─────────┴─────────┴─────────┴─────────┘
```

- 四个图标等宽排列，顺序固定：对话 · 记忆 · 外观 · 设置。
- 图标风格沿用桌面现有的 Nucleo Glass 乳白底；进入全屏 App 后不显示底栏（和现在一样）。
- 「记忆」目前只是存放手动收藏内容的 App；**自动记忆尚未实现**。

### 一条 AI 回复长什么样

每条 AI 回复是 **一张完整卡片**，从上到下三块：

```
┌──────────────────────────────────────┐
│ 时间栏                                │  ← 整条回复共用，只有一个
├──────────────────────────────────────┤
│ 正文                                  │
│   线下：雨停的时候已经快十一点了……     │
│                                      │
│   线上： ○ [到家了吗？]               │
│                     [还没，在躲雨] ○  │
│                                      │
│   线下：你把伞抖了抖……                │
│   （线上线下可以任意穿插、任意多段）    │
├──────────────────────────────────────┤
│ 状态栏                                │  ← 整条回复共用，只有一个
└──────────────────────────────────────┘
```

- **时间栏**（最上）：这条回复的时间。
- **正文**（中间）：线上和线下按模型写的顺序从上往下排。
- **状态栏**（最下）：沿用现在 moom 状态栏的内容（头像、名字、楼层、可编辑的自定义文字等），具体怎么分配给时间栏和状态栏，实现时再细化。
- 时间栏和状态栏属于 **整条回复**，不跟着正文里的某一段走；正文里有几段线上、几段线下，都只有这一个时间栏和一个状态栏。

## 2. 基本规则

### 2.1 标签

- 线上内容写在 `<live>` 与 `</live>` 之间，标签单独占一行最好，但写在同一行也要认。
- 一条回复里可以有任意多个 `<live>` 块。
- `<live>` 不嵌套；块里又出现 `<live>` 时当作普通文字处理。

### 2.2 一行一个气泡

在 `<live>` 里：

1. **一行以 `char：` 或 `user：` 开头，就开一个新气泡。** 全角冒号 `：` 和半角冒号 `:` 都认，冒号后面的空格可有可无。
2. **不以名字开头的行，算上一条气泡里的换行。** 想在一条消息里换行，直接换行就行。
3. **空行忽略**，不会生成空气泡。
4. 居中类消息（拍一拍、系统提示等，见第 3 节）单独一行、不写名字，以 `[类型]` 开头。

例子：

```text
<live>
char：hi
好久不见啊
最近怎么样
char：在吗
user：在的
</live>
```

结果是 **三个气泡**：char 的第一个里有三行字，char 的第二个是「在吗」，user 一个「在的」。

### 2.3 左右和头像

- `user` 的气泡放 **右边**，`char` 的放 **左边**。
- 名字只认 `char` 和 `user` 两个写法（大小写都认），模型不要自己起名。
- 名字前缀 **不显示** 在气泡里。
- 头像和显示名：char 从当前角色卡取，user 从用户资料取。**不让模型写头像文件名或图片地址**，写了也不用。

### 2.4 特殊消息

- 名字后面紧跟 `[类型]`，就是特殊消息，例如 `char：[语音] 到家了吗`。
- 不跟方括号就是普通文字。
- 方括号前后的空格可有可无。

### 2.5 竖线分字段

有的类型有多个字段，用竖线 `|` 隔开（全角 `｜` 也认）。

- 只按这个类型 **需要的竖线数量从左往右切**，多出来的竖线全部算进最后一个字段。
  - 例：`[转账] 52|奶茶|和蛋糕钱` → 金额 `52`，备注 `奶茶|和蛋糕钱`。
  - 例：`[引用] 到家了吗|快到了|你呢` → 原话 `到家了吗`，回复 `快到了|你呢`。
- 每个字段前后的空格去掉。

### 2.6 用户自己发的消息

- 用户在输入框里写的内容 **一律当普通消息**，**不解析** `<live>`。
- 用户想在手机上发消息时，用自然语言告诉模型，以 `$线上聊天：` 开头，例如：
  - `$线上聊天：给char发信息："到家了吗"`
  - `$线上聊天：给char转账：52元`
- 模型理解后，在回复 **开头** 用 `<live>` 里的 `user` 行把这条消息复现出来（比如 `user：到家了吗`、`user：[转账] 52|`），再接着往下写。
- 这条约定写在预设提示词里（见 5.1），app 本身不对 `$线上聊天：` 做特殊处理。

## 3. 消息类型（线上）

### 3.1 有发送人的消息（分左右）

| 类型 | 写法 | 示例 | 显示效果 |
| --- | --- | --- | --- |
| 文字 | `char：内容` | `char：到家了吗` | 普通聊天气泡 |
| 语音 | `char：[语音] 文字\|秒数` | `char：[语音] 外面好冷啊\|8秒` | 语音条，显示秒数；点一下在下方展开文字。秒数由模型写；没写时按字数估算 |
| 图片 | `char：[图片] 描述` | `char：[图片] 窗外的路灯，有点糊` | 一张占位小图（主题色 + 图片图标）；点开显示描述。**不加载任何外部图片** |
| 表情包 | `char：[表情] 描述` | `char：[表情] 小猫探头` | 先显示成带表情标记的小号文字；以后可接图库里的表情 |
| 红包 | `char：[红包] 祝福语` | `char：[红包] 早点睡` | 红包卡片，写着祝福语；祝福语空时显示「恭喜发财，大吉大利」 |
| 转账 | `char：[转账] 金额\|备注` | `char：[转账] 52\|奶茶钱` | 转账卡片：大号金额 + 小字备注 |
| 定位 | `char：[定位] 地点名\|地址` | `char：[定位] 便利店\|樱町二丁目` | 位置卡片：地点名 + 灰色地址 + 简单的地图示意块（不加载真实地图） |
| 引用 | `char：[引用] 被引用原话\|回复内容` | `char：[引用] 到家了吗\|快到了` | 气泡正文是回复内容，正文上方带一小块灰底的被引用原话 |
| 链接分享 | `char：[链接] 标题\|简介` | `char：[链接] 那家店\|樱町的面包店` | 小卡片：标题 + 简介。不能点开外部网页 |
| 音乐分享 | `char：[音乐] 歌名\|歌手` | `char：[音乐] 晴天\|周杰伦` | 音乐卡片：歌名 + 歌手 + 唱片图标；以后可连到音乐 App |
| 通话记录 | `char：[通话] 状态\|时长或时间` | `char：[通话] 未接\|23:41` <br> `user：[通话] 通话时长\|12:05` | 带电话图标的小气泡，例如「未接 23:41」「通话时长 12:05」 |
| 被拒收 | `user：[拒收] 被拒收的消息内容` | `user：[拒收] 你到底怎么了` | 普通的右侧气泡，内容照常显示；气泡旁边挂一个 **红色感叹号**；气泡下方一行小灰字「消息已发出，但被对方拒收了」 |

除「被拒收」只用于 `user` 外，以上 `char：` 都可以换成 `user：`，气泡换到右边即可。

### 3.2 已读未回

| 类型 | 写法 | 示例 | 显示效果 |
| --- | --- | --- | --- |
| 已读 | `[已读]` 单独一行 | `[已读]` | 不单独成气泡；挂在 **前面最近一条 user 气泡** 下方，显示小字「已读」。前面没有 user 气泡时忽略 |

### 3.3 居中类（不分左右，单独一行，不写名字）

| 类型 | 写法 | 示例 | 显示效果 |
| --- | --- | --- | --- |
| 拍一拍 | `[拍一拍] 文本` | `[拍一拍] char 拍了拍 user 的头` | 居中灰色小字 |
| 系统提示 | `[系统] 文本` | `[系统] 对方已开启好友验证` | 居中灰色小字 |
| 撤回 | `[撤回] 文本` | `[撤回] char 撤回了一条消息` | 居中灰色小字（「点一下偷看原文」以后再说） |
| 时间分隔 | `[时间] 文本` | `[时间] 昨天 23:12` | 居中的小号时间，上下多留一点空 |

文本里出现的 `char`、`user` 会替换成角色名和用户昵称再显示。

**不做「正在输入」。**

### 3.4 完整示例：线下和线上穿插

用户输入：

```text
$线上聊天：给char发信息："还没到家，在便利店躲雨"
```

模型原样输出：

```text
<live>
user：还没到家，在便利店躲雨
</live>

雨停的时候已经快十一点了。你站在便利店门口，手机震了一下。

<live>
[时间] 23:02
char：到家了吗？
外面好像还挺冷的
char：[语音] 我刚下班，路上风好大|6秒
user：[引用] 到家了吗？|还没，在便利店躲雨
[已读]
</live>

你把伞抖了抖，玻璃门上映出一片模糊的路灯光。过了好一会儿，屏幕才又亮起来。

<live>
char：[通话] 未接|23:09
char：[定位] 樱町便利店|樱町二丁目 3-1
char：那我过去接你？
char：[表情] 小猫举伞
user：[拒收] 不用了
[拍一拍] char 拍了拍 user 的头
</live>

你还没来得及回，就听见街角传来熟悉的脚步声。
```

显示出来是 **一张卡片**：

1. 最上面：时间栏。
2. 正文：
   1. 线上：右边 user 气泡「还没到家，在便利店躲雨」（复现用户刚才发的消息）。
   2. 线下：整段文字。
   3. 线上：居中时间「23:02」；左边 char 一个气泡（两行字：「到家了吗？」「外面好像还挺冷的」）；左边一个 6 秒的语音条；右边 user 的引用气泡（上方小块「到家了吗？」，正文「还没，在便利店躲雨」），下方小字「已读」。
   4. 线下：整段文字。
   5. 线上：左边「未接 23:09」的通话记录、位置卡片、文字气泡「那我过去接你？」、表情描述；右边 user 气泡「不用了」，旁边红色感叹号，下方小灰字「消息已发出，但被对方拒收了」；最后一行居中灰字「（角色名）拍了拍（用户昵称）的头」。
   6. 线下：整段文字。
3. 最下面：状态栏。

## 4. 写错了怎么办（兜底规则）

原则：**模型写错了，最多显示得不够漂亮，绝不能把界面弄乱、弄丢内容。**

1. **`<live>` 没闭合**：从 `<live>` 开始一直到这条回复结尾，都当作线上处理。
2. **只有 `</live>` 没有 `<live>`**：这个多出来的结束标签直接隐藏。
3. **认不出来的类型**（比如 `[跳舞]`）**或格式不对**：整行当普通文字气泡显示，方括号原样保留。
4. **`<live>` 里第一行没写名字**：当作 char 的消息。
5. **字段不够**（比如转账只写了金额没写备注）：缺的字段留空，卡片照常显示。语音没写秒数时，按字数估算。
6. **原始标签不能露出来炸版面**：`<live>`、`</live>` 本身永远不直接显示；任何解析不了的东西都退回成普通文字。
7. **安全**：
   - **线上气泡里的文字一律转义**后显示，气泡里写 HTML 也只会原样显示成文字。
   - AI 输出区域是自由的：模型在正文里写的 HTML / CSS / JS 代码，放进一个 **隔离的小框**（sandbox iframe）里运行，样式、动画、小交互都能显示，**小框里的代码可以联网**（加载外部图片、字体等）。
   - 这个小框 **不带 `allow-same-origin`**，访问不到 app 的 localStorage、API key 和父页面。
   - 模型写的代码 **只在隔离小框里执行，绝不直接插进 app 页面**。

## 5. 这份规范落在三个地方

| 位置 | 给谁看 | 作用 |
| --- | --- | --- |
| **本文档** `docs/LIVE_FORMAT.md` | 人 | 唯一标准。以后要加、改类型，先改这里，另外两处跟着改 |
| **预设里的格式说明** | 模型 | 告诉模型线上怎么写、每种消息的格式。模型就是靠这段才会这样输出 |
| **前端解析和样式**（以后实现） | 程序 | 把 `<live>` 认出来、画成对应气泡。用户不需要自己写正则 |

### 5.1 可直接粘进预设的提示词草稿

```text
【输出格式】
正文有线上、线下两种写法，由你按剧情自行选择，可以只用一种，也可以穿插。
- 线下：现实中发生的事（动作、环境、心理），直接写正文。
- 线上：角色之间用手机发消息，把聊天内容放进 <live> 和 </live> 之间。

<live> 内规则：
- 每条消息另起一行，以「char：」或「user：」开头。char 是你扮演的角色，user 是用户。
- 同一条消息内需要换行时，直接换行，不要重复写名字。
- 特殊消息在名字后加类型，多个字段用 | 分隔：
  [语音] 文字|秒数　[图片] 描述　[表情] 描述　[红包] 祝福语
  [转账] 金额|备注　[定位] 地点名|地址　[引用] 被引用原话|回复内容
  [链接] 标题|简介　[音乐] 歌名|歌手　[通话] 状态|时长或时间
  user：[拒收] 内容（表示 user 的这条消息被 char 拒收）
- 下列消息单独一行、不写名字：
  [已读]　[拍一拍] 文本　[系统] 文本　[撤回] 文本　[时间] 文本
- 不要写头像或图片链接。

【用户的线上消息】
用户以「$线上聊天：」开头时，表示用户在手机上发消息。
请在回复开头用 <live> 里的 user 行复现用户这条消息，再接着写。

示例：
<live>
user：还没到家，在便利店躲雨
</live>
雨停的时候已经快十一点了。
<live>
char：到家了吗？
char：[语音] 外面好冷啊|5秒
</live>
```

### 5.2 给以后写代码的人

- 解析器只处理 AI 回复的文字，输出一串「线下段 / 线上气泡 / 居中提示」，再交给模板画出来；解析和画图分开。
- 每条 AI 回复渲染成一张卡片：时间栏 + 正文 + 状态栏，时间栏和状态栏整条只有一个。
- 线上气泡内的文字一律转义。正文里模型写的 HTML / CSS / JS 只放进 sandbox iframe（不带 `allow-same-origin`，用 `srcdoc` 装内容），绝不直接插进 app 页面。小框内允许联网加载外部图片、字体等资源；即使联网，也读不到 app 的 localStorage 和 API key。
- 沿用项目习惯：给每个区域加稳定的 `data-live-part`（例如 `bubble`、`voice`、`image`、`transfer`、`rejected`、`center`、`read`），以后换皮肤只改 CSS。
- **颜色全部走主题变量**（如 `--accent`、`--ink`、`--muted`、`--glass-tint`、`--bubble-bg`、`--bubble-rim`；被拒收的红色感叹号也用一个主题里的警示色变量，默认红色），支持以后的马卡龙主题和夜间模式；**不写死颜色；app 自己画的气泡和卡片不用外部图片**（模型写在隔离小框里的代码除外），图标用项目内的线条 SVG。
- 线下沿用 moom 现有的阅读排版（`src/apps/moom/default.css`）；线上气泡沿用现有聊天气泡样式，现有的语音、引用样式能复用就复用。
- 系统开启「减少动效」时关掉语音条跳动等动画。

## 6. 合并时旧数据必须保留

合并只改入口和显示方式，**不删、不清空、不改写旧数据**。以下内容合并后都要能在「对话」里打开重读：

- 旧 moom 的所有场景（进行中、暂存、已结束、邀请中、稍后赴约）
- 场景与聊天的关联（`sessionId`、聊天卡片的 `storyLink`）
- 结束小记和聊天里的记录卡
- 状态栏自定义文字（`statusText`）和状态卡内容（`statusPanel`）
- 输入框草稿
- 纸质邀请函（信封、信纸、`wait` / `Readily`）照常使用
- 图库、音乐、ZIP / JSON 备份和本机快照，格式保持兼容

旧场景里的正文本来就是叙述 / 台词 / 行动，没有 `<live>`，按线下显示即可，不需要转换。

## 7. 已确认的决定

1. **术语**：统一叫「线上」「线下」。它们是正文的两种表达形式，不是两种会话；界面不显示线上 / 线下标签、没有切换按钮、不区分会话类型；用哪种完全由模型按剧情判断。
2. **旧 moom 剧情**：不单独分组，和其他对话一起按时间排，点进去照常重读。
3. **用户输入**：一律当普通消息，不解析 `<live>`。想走线上时用自然语言告诉模型（如 `$线上聊天：给char发信息："xxx"`、`$线上聊天：给char转账：xxx元`），模型在回复开头用 user 行复现，再接着写。
4. **AI 输出区域是自由的**：模型写的 HTML / CSS / JS 在隔离小框（sandbox iframe，无 `allow-same-origin`）里运行，允许联网；线上气泡文字仍一律转义；代码绝不直接插进 app 页面。
5. **回复卡片**：每条 AI 回复是一张卡片，从上到下为时间栏、正文、状态栏；时间栏和状态栏整条回复共用。
6. **语音秒数**：由模型写，`char：[语音] 文字|8秒`；没写时按字数估算。
7. **被拒收**：`user：[拒收] 被拒收的消息内容`，显示成普通右侧气泡，旁边红色感叹号，下方小灰字「消息已发出，但被对方拒收了」。
